# 🔗 증거 사슬 다홉 추론 — 인용되거나 침묵하거나

## 💡 핵심 요약
"두 기억이 어떻게 이어지는지" 물을 때, 답은 **vault 안의 실제 증거로 놓은
사슬**이거나, 아니면 정직한 **"증거로 이을 수 없어요"** 예요 — 그 사이엔
발명이 없어요 (`brain_engine/chain_reasoner.py`). Fable 류 고도 추론을
**외부 모델 없이** 두뇌 소유의 그래프 탐색으로 재주조했어요.

## 🔩 증거 3종 (edges_of — 전부 vault 사실에서)
1. **link** — 한 노트의 `[[위키 링크]]` 가 다른 노트 제목을 지목
2. **tag** — 두 노트가 공유하는 태그 (1개 이상)
3. **ident** — 기계 채널의 공유 식별자 (`호출:`/`참조:` 행의 토큰 겹침)
엣지 하나하나가 노트 파일에 실제로 적힌 것. 추측 간선은 없어요.

## 🔩 추론 규칙 (reason)
- 질문을 `'A 와 B'` 두 **초점**으로 쪼개 (`_foci`), 각 초점을 vault 에서
  가장 겹치는 노트에 대응 (`_best`).
- **한쪽 초점이라도 vault 에 없으면** → 사슬을 짓지 않고 거부 (없는 기억을
  지어내지 않아요). 양쪽이 같은 노트여도 거부.
- 두 초점 사이 **BFS ≤ 3 홉**. 닿으면 사슬 노트의 제목·요약과 다리 증거
  (`type(bridge)`) 만으로 답을 조립 — 새 주장 추가 금지.
- 닿지 않으면 `"두 초점 기억 사이에 사슬이 닿지 않아요 (구멍 보고)"`.

## 🔩 감사 (quest_runners chain 퀘스트의 audit 스텝)
reason 이 내놓은 각 엣지를 **실제 노트 파일과 대조**해요: link 면
`[[제목]]` 이 파일에 있는지, tag·ident 면 다리 토큰이 두 파일에
(대소문자 무시 — `edges_of` 가 소문자화하므로) 있는지. `audit_ok` 가
proof 로 남아요 — "답했다"와 "답이 파일로 확인됐다"를 분리.

## 📈 실측
- 2-홉 양성 벤치마크(vault 구조에서 자동 조성) **6/6** 사슬 유효.
- 고립 노트(합성 island) 질문 → `known: False` **발명 거부**.
- 한쪽 초점만 실재하는 질문 → `known: False` (정직).
- 라이브 `POST /api/reason` + chain 퀘스트 `audit_ok: True` (파일 대조 확인).

## 🧭 한계 (정직 고지)
다홉이어도 **증거가 있는 길만** 걸어요. vault 에 간선이 없으면 1홉도
못 잇고, 그걸 "몰라요"로 보고하는 것이 특징이지 결함이 아니에요. 의미
유사도(코사인)로 간선을 짓지 않아요 — 코드 채널 코사인 금지 원칙 그대로.
